## 독창성: 85 / 100

구구단 출력 자체는 강의에서 제시한 기본 문제이므로 완전히 새로운 문제 해결이라고 평가하지 않았습니다. 대신 요구사항을 안정적으로 처리하고 출력 구조를 일반화하는 데 집중했습니다.

단순히 단별 출력문을 작성하는 대신, 최대 단수의 자릿수로 전체 표의 공통 열 폭을 계산했습니다. 이 방식은 1~5단과 11~15단처럼 숫자 길이가 다른 묶음도 같은 다섯 개의 세로 격자에 배치합니다. 끝난 단은 공통 폭의 공백 셀로 처리하여 삼각형 구조와 열 정렬을 함께 유지했습니다.

입력은 `atoi`나 스트림의 부분 변환 결과에 의존하지 않고 문자열 전체를 한 글자씩 검사했습니다. 범위 초과도 실제 누적 계산 전에 차단하며, 명령행과 재입력에 동일한 파서를 적용했습니다. 출력은 전체 표를 저장하지 않고 한 행씩 만들어 기록하므로 문제에서 요구한 모든 식을 생성하면서 추가 메모리를 제한했습니다.

## 학습한 점과 유용성

- Visual Studio 솔루션과 Release/x64 빌드 구성을 직접 다뤘습니다.
- `argc`, `argv`를 통한 명령행 입력과 대화형 재입력의 차이를 이해했습니다.
- 입력 검사, 실행 흐름, 출력 책임을 분리하면 코드 검토와 수정이 쉬워진다는 점을 확인했습니다.
- 콘솔 표에서는 계산뿐 아니라 숫자 폭과 빈 셀을 함께 설계해야 정렬이 유지된다는 점을 배웠습니다.
- 요구사항을 자동 테스트 가능한 조건으로 바꾸고 실제 출력 전체를 비교하는 방법을 경험했습니다.

## 참고 자료와 도구 사용

과제의 기능과 문서 구성은 강의 PDF, 강의 설명 원문, 교수자가 제공한 실행 예시를 기준으로 해석했습니다. 구현·주석·문서 작성과 자동 검증 과정에서는 OpenAI Codex를 보조 도구로 사용했습니다. 요구사항의 최종 선택과 출력 모양 확인은 작성자가 수행했으며, 문서의 실행 결과와 수치는 최종 프로그램을 실제로 빌드하고 실행한 결과만 기록했습니다.

다른 학생의 완성 코드를 복사하거나 실행하지 않은 결과를 실제 결과처럼 작성하지 않았습니다. 사용한 알고리즘은 과제 조건에 맞춰 구성했으며, 소스에는 각 선택이 필요한 이유를 한국어 주석으로 설명했습니다.

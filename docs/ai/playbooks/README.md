# Playbooks

Read one primary playbook for the current task and add another only when its boundary is genuinely involved.

| Playbook | Use when |
|---|---|
| [Discovery](discovery.md) | defining a project, milestone, or unfamiliar system |
| [Feature](feature.md) | implementing an approved behavior |
| [Bug fix](bugfix.md) | reproducing, diagnosing, and minimally fixing a defect |
| [CI failure](ci-failure.md) | a remote or deterministic check fails |
| [Cross-platform](cross-platform.md) | operating systems or architectures differ |
| [Environment recovery](environment-recovery.md) | local tools or virtual environments are broken |
| [UI change](ui-change.md) | visible interaction or layout changes |
| [Dependency change](dependency-change.md) | adding packages, binaries, licenses, or supply-chain inputs |
| [Commit and PR](commit-pr.md) | publishing a verified local change |
| [Post-merge](post-merge.md) | synchronizing and verifying merged main |
| [Release](release.md) | packaging, deployment, tag, or release assets |
| [Handoff](handoff.md) | pausing or transferring work |

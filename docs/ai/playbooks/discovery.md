# Discovery Playbook

## Outcome

A fact-based plan with explicit decisions, risks, milestones, and evidence—not implementation.

## Procedure

1. Inspect repository instructions, docs, branch, working tree, recent history, and relevant code read-only.
2. Separate verified facts, uncertain assumptions, and current external facts requiring official-source research.
3. Define users, problem, success flow, non-goals, data boundary, platforms, and constraints.
4. Identify the smallest real end-to-end milestone and its manual acceptance owner.
5. Propose architecture boundaries, files, tests, rollback, and stop conditions.
6. Ask only questions whose answers materially change the safe result.
7. Present an approval request; do not mutate the project during discovery.

## Evidence rule

Use repository and primary-source evidence. Never turn chat memory, an outdated guide, or an unverified URL into a product fact.
